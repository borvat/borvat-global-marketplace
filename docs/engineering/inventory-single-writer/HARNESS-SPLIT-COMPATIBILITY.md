## 2. التوافق مع كل بيئة

| البيئة | الحالة المفترضة | ما يحدث بعد التقسيم |
|---|---|---|
| الإنتاج (Supabase) | الملفان مطبَّقان منذ تموز، والجدول موجود | لا يُنفَّذ أي SQL: `db push` يقارن النسخ لا المحتوى، فالنسختان مسجّلتان ⇒ تخطٍّ كامل. المحتوى الجديد يخصّ بناءً من الصفر فقط |
| Staging (إن وُجد) | مثل الإنتاج إن كان بُني بالترحيلات | نفس السلوك: تخطٍّ |
| قاعدة جديدة / CI | بناء من الصفر | تُطبَّق النسخة المقتطعة، فينجح البناء بدل أن يفشل ويُسقط الكائنات |
| بيئة فشل فيها الملف تاريخياً | الجدول غائب (الملف أُلغي) | **خطر**: التقسيم يجمّد الغياب، لأن النصف DDL لن يُعاد تشغيله (النسخة مسجّلة). يجب كشف هذه الحالة ومعالجتها قبل الدمج |

**كشف الحالة الخطرة** قبل أي دمج، في كل بيئة:

```sql
SELECT to_regclass('public.merchant_store_sku_delivery_promise_assignments') AS table_present,
       to_regnamespace('internal_shipping') AS shipping_schema;
```

إن كان أياً منهما `NULL` فوقاعدة البيئة تعتبر ناقصة: تحتاج ترحيل إصلاح أمامي قبل أو مع التقسيم، لا بعده.

## 4. خطة التنفيذ الآمنة (سبع بوابات)

1. **سجّل الحالة:** في كل بيئة، استعلم `supabase_migrations.schema_migrations` للنسختين، واحفظ الناتج. لا تُكمل إن كانت إحداهما `pending`.
2. **افحص الكائنات** بالاستعلام أعلاه. أي `NULL` ⇒ أوقف واكتب ترحيل إصلاح أمامي أولاً.
3. **افحص البصمات:** احفظ SHA256 للملفين قبل التعديل، وبعده، وسجّلهما مع القرار.
4. **ادمج محتوى الملفين فقط** (لا إعادة تسمية، لا تغيير طابع زمني) في فرع، ثم أعد بناء قاعدة رمي كاملة وتأكد 131/0/1.
5. **دُفعة النشر:** `supabase db push` في بيئة غير إنتاجية أولاً. تحقّق أن `migration list` لم يتغيّر عدد صفوفه، وأنه لم يُنفَّذ أي SQL جديد.
6. **إن كانت أدواتك تحسب بصمة محتوى** (CI diff / migration checksum): أضف استثناءً موثّقاً للنسختين، وإلا فسيفشل الفحص بلا سبب وظيفي.
7. **التراجع:** `git revert` لمحتوى الملفين. لا إجراء على قاعدة البيانات في أي بيئة، لأن لا شيء نُفِّذ.

## 5. الأثر على الإنتاج: صفر

- لا يُرسل أي SQL إلى قاعدة قائمة.
- لا يتغيّر صف في سجل الترحيلات.
- الكائنات الموجودة تبقى كما هي.
- الفائدة كلها في البيئات الجديدة: بناء كامل بدل بناء ناقص.

1. الموافقة على الدمج بعد اجتياز البوابات السبع، أو
2. تثبيت التقسيم على الفرع المعزول كمرجع دائم دون دمج.

لا شيء من هذا ينفّذ حتى تقول ذلك صراحة.
