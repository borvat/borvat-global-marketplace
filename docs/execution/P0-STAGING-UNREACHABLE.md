# P0 — Staging unreachable: السبب الجذري والإصلاح

**الخدمة:** `borvat-marketplace-staging-verified` (`srv-dbdr4rgm7kps73bdvmfg`)
**الرابط:** https://borvat-marketplace-staging-verified.onrender.com
**التاريخ:** 2026-11-02
**الحالة:** أُصلح على staging فقط. القبول النهائي ينتظره اختبار متصفح بعد إيقاظ بارد.

## السبب الجذري

فحص الصحة كان مضبوطاً على `/`، وهو مسار SSR. على نسخة باردة (0.1 CPU، ذاكرة تخزين مؤقت فارغة) يتجاوز أول طلب SSR نافذة فحص الصحة في Render، فلا تُعلَّم النسخة سليمة، ويعيد Render تدويرها، فيبقى البروكسي على شاشة **SERVICE WAKING UP**، والطلبات الخارجية تُعلَّق بلا أي بايت.

**الأدلة، بالخط الزمني (UTC):**

| الوقت | الحدث | المصدر |
|---|---|---|
| 00:47:08 | تشغيل العملية | runtime log |
| 00:47:09 | `Listening on ... :10000 (all interfaces)` | runtime log |
| 00:47:19 | `Your service is live` (10 ثوان) — النسخة كانت دافئة من البناء | runtime log |
| 01:05:41 | `Stopping server gracefully` — إيقاف خمول | runtime log |
| 01:36:23 | إعادة تشغيل عند الطلب | runtime log |
| 01:36:24 | `Listening` — الإقلاع ثانية واحدة | runtime log |
| بعد 01:36 | **لا سطر `Your service is live`** | runtime log |
| 01:36:51 | `GET /` → **000** بعد 60 ثانية بلا بايت | قياس خارجي |
| ~01:37 | `/discover` → **000** | قياس خارجي |
| 01:40:03 | `/` 200 في 0.37s، `/discover` 200 في 0.46s | قياس خارجي |
| 01:41:23 | `Running` ثم `Listening` 01:41:25 | runtime log |
| **01:41:36** | **`Stopping server gracefully` بعد 11 ثانية من الإقلاع** — تدوير نسخة فشلت في الفحص | runtime log |

**الاستدلال:** الإقلاع ليس المشكلة (1-2 ثانية)، ولا يوجد OOM ولا انهيار. الظاهرة هي فشل فحص الصحة على مسار SSR بارد، ثم تدوير النسخة، ثم شاشة الإيقاظ. عند نجاح أول طلب SSR تصبح كل المسارات سريعة (0.4s)، وهذا ما يفسّر «تعمل أحياناً» عند المالك.

**ما استُبعد:** تعليق البروكسي (الهيدرز تحمل `rndr-id` من Render)، فشل ربط المنفذ (السجل يعلن الاستماع على 10000 وعلى كل الواجهات)، انهيار التطبيق (لا سطر خطأ واحد)، وفشل HEAD (HEAD على `/` و`/discover` والأصول يرجع 200).

**قيود في التشخيص:** سجلات الطلبات غير متاحة على الخطة المجانية (`type=request` يعيد صفراً)، وسجل البناء السابق غير متاح عبر الـAPI. المعامل الصحيح لسجلات Render هو `resource` وليس `resourceIds`، وقد استُخدم.

## تفسير الشاشة التي رآها المالك

لم يكن الموقع معطلاً ولا منهاراً. كان Render يحاول نسخة لا تُقبل كسليمة، فيعرض صفحة الانتظار. بعد الإصلاح تصبح النسخة «live» بمجرد فتح المنفذ، وأول طلب ينتظر مدة الإقلاع البارد فقط.

## حدود معلنة

- الخطة المجانية تنام بعد ~15 دقيقة خمول، فأول طلب بعد النوم بطيء بحكم الخطة، لا بحكم الكود.
- إزالة فحص الصحة تعني أن Render لا يتأكد من صحة المسار قبل تحويل الترافيك. المقابل: لم يبقَ فحص يدور على مسار SSR بارد.
- لا يزال لا يوجد مسار صحة خفيف في التطبيق. الحل الدائم: إضافة ملف ثابت (`public/health.txt`) ونقله إلى فحص الصحة في نشر لاحق.

## اختبار المتصفح بعد الاستيقاظ

أول طلب من متصفح خارجي بعد 15 دقيقة خمول:

| اللحظة | ما ظهر |
|---|---|
| t+1.4s | `Render - Application loading` (شاشة انتظار Render) |
| t+~8s إلى 20s | صفحة المتجر فعلياً. `Ontdek onze collectie · BORVAT`، `h1` صحيح، وسكربتات التطبيق محمّلة |

| المسار | الزمن | العنوان |
|---|---|---|
