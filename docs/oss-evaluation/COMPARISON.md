None was stress-tested against the target scale. Proposed production shape is API processes + separate background workers, managed PostgreSQL, a durable event/outbox/inbox boundary, object storage and controlled cache/search. Prove contention, queue recovery, PITR restore, migration rollback and tenant-scoped analytics in C6. Never infer horizontal scaling from a framework label.

## Selection reasoning

Mercur is the preferred foundation because its implemented seller/product/offer/payment split domain matches BORVAT with the least new bespoke commerce logic and compatible TypeScript tooling. Vendure is the runner-up because its actual channel/order strategy implementation is a credible independent architecture; the marketplace layer remains educational and requires more adaptation. Medusa alone would duplicate Mercur's marketplace work. Saleor adds a second language/runtime without removing the need for a seller/commission/settlement layer.

This is an engineering judgment with medium confidence, not a vendor endorsement or a scored benchmark. The recommendation is conditional on dependency triage, enforceable staff roles, buybox/offer policy, legal license review and a passing BORVAT end-to-end acceptance gate. Our core's 37 passing tests are valuable reusable specifications and implementation candidates, not evidence that the entire current product is complete.
