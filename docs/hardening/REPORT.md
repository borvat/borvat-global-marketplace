## Source pins and repeatability

Mercur 2.3.7 at `57fa9cf7de35829ce493a3ace29deb4f36d0838b`, tested with Medusa **2.21.2**, Node 24.19.0, Bun 1.3.8 and isolated PostgreSQL 17.6. Medusa 2.22 source inspection is not compatibility certification. Native source was not patched to hide H06; only isolated test specs, dependency candidates and build artifacts were added. Three tested overrides: lodash 4.18.1, express 4.22.3, @graphql-tools/utils 13.1.1. Fourth proxy override is rejected as incomplete by H07.

[Reproduction scripts](../../experiments/mercur-hardening/reproduction) capture lab paths/commands and are not turnkey production tools. Start from the pinned upstream clone and dependency graph; place the two native specs under integration-tests/http/borvat, run build then targeted native suites sequentially with PostgreSQL. The runtime network guard permits loopback only. No Redis-backed production queue was exercised. Native tests use upstream test adapters/fake Redis.

Host limitation: isolated container maps only root and disallows Unix sockets. PostgreSQL starts with loopback TCP and a host-only first-geteuid startup shim; application tests use explicit NOSUPERUSER/NOBYPASSRLS roles. The shim is never loaded into business Node processes. Repeat on an ordinary non-root PostgreSQL host before database operational approval. Evidence is not a claim of hardened host deployment.

Payment proof uses two independent synthetic databases, never a payment account. Child SIGKILL occurs after provider commit; a fresh process reconciles without a second charge. Historical unknown outcomes stay manual-review when lookup cannot establish facts. Restoration is an application logical snapshot, not pg_dump/PITR. Refund, chargeback and native settlement coverage remain required.

Native counts are successive runs, not additive unique coverage: baseline 75 pass / 2 skip; own 11 pass; combined after three overrides 86 pass / 2 skip. The later four-override diagnostic runs a subset (24 pass / 2 fail). Do not sum these into a larger passing total. Compressed Jest result JSON accompanies each native run.

## Cost, residual risk and acceptance recommendation

Prior planning range remains 65–100 engineering days and €69,850–116,000 over twelve months under the prior assumptions. Reserve approximately 10–20 days (€6,500–13,000 at €650/day) within that range for remaining hardening; this is a planning allocation, not an additional vendor quotation or guarantee. Native financial refactoring, asset recovery and cross-system contracts could increase it. No paid service was purchased. Hosting/PSP fees remain volume/provider dependent and unquoted.

Critical acceptance blockers are native financial evidence loss, actual vulnerable dependency resolution, residual high/critical graph findings, incomplete native job authorization, unrecovered assets/build failure, and absent full end-to-end integration/operational restore evidence. Keep Mercur as the design candidate, reject final adoption at this gate, and retain the existing BORVAT sources unchanged. Owner review of evidence and explicit stage approval are required after blockers close. No Codex job, merge, deployment, real seller, live provider or production data change was performed.
